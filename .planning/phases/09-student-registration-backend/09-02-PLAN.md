<objective>
Implement the complete student self-registration and admin approval pipeline. Students register publicly with their SBRN (Student Board Roll Number), email, and password. Accounts start as `pending`. Admins review registrations, approve or reject them. Approved students receive an HTML email with their SBRN login credentials. The frontend has a public `/register` page and an admin `/admin/approvals` dashboard with live pending-count badge on the sidebar.
</objective>

## Tasks

### Task 1: Self-registration endpoint (public)

Create `POST /api/auth/register` in `registrationRoutes.js` / `registrationController.js`:
- Validate: full_name (≥3 chars), SBRN (alphanumeric + `-_`), email, password (≥6), confirm_password match
- Normalize SBRN to uppercase (e.g., `STU-001`)
- Duplicate checks: email already in profiles, SBRN already in students
- `supabase.auth.admin.createUser()` with `email_confirm: true`
- Upsert `profiles` row: `approval_status: 'pending'`
- Upsert `students` row: `student_id_text: sbrn, status: 'inactive'` — enables SBRN→email lookup at login
- Rate-limited to 5 attempts per 15 minutes per IP

### Task 2: Admin approval/rejection endpoints

Create `GET /api/admin/pending-users`, `GET /api/admin/all-registration-users`, `POST /api/admin/approve/:id`, `POST /api/admin/reject/:id` in `approvalRoutes.js` / `approvalController.js`:
- All routes gated by `authMiddleware + requireRole('admin')`
- Approve: set `profiles.approval_status → 'approved'`, set `students.status → 'active'`, fire approval email
- Reject: set `profiles.approval_status → 'rejected'`, fire rejection email
- Both email sends are fire-and-forget (non-fatal if SMTP not configured)

### Task 3: Nodemailer email service

Create `backend/utils/emailService.js`:
- Lazy transporter — only instantiated when SMTP env vars are present; falls back gracefully with a warning
- `sendApprovalEmail({ to, name, sbrn })` — HTML email with SBRN callout box and sign-in CTA
- `sendRejectionEmail({ to, name })` — HTML email with rejection notice and contact-admin info
- Both have plain-text fallbacks for email clients that don't render HTML

### Task 4: Frontend registration page

Create `src/app/pages/RegistrationPage.tsx` — public page at `/register`:
- Fields: Full Name, SBRN, Email, Password, Confirm Password
- Calls `backendRegisterSelf()` from `backendApi.ts`
- Shows pending-approval message on success
- Link from LoginPage's "Don't have an account?" area

### Task 5: Admin approvals dashboard + backend API client

Create `src/app/pages/AdminApprovals.tsx` — admin-only page at `/admin/approvals`:
- Filter tabs: All / Pending / Approved / Rejected with live counts
- Search by name or email
- Approve / Reject action buttons with optimistic UI updates
- Pending registration count badge on sidebar via `backendGetPendingUsers()`

Extend `src/app/lib/backendApi.ts` with all new endpoint wrappers:
- `backendRegisterSelf()`, `backendGetPendingUsers()`, `backendGetAllRegistrationUsers()`, `backendApproveUser()`, `backendRejectUser()`
