<objective>
Build a secure Node.js/Express.js backend server that isolates the Supabase service role key from the browser. Implement JWT-based authentication middleware that validates tokens against the `public.profiles` table (not JWT metadata, to prevent spoofing). Build the core auth endpoints and admin-only student management CRUD endpoints.
</objective>

## Tasks

### Task 1: Initialize Express backend with security middleware

Create `backend/` directory with Express.js server. Install and configure:
- `helmet` — security headers
- `cors` — allow only the frontend origin
- `express-rate-limit` — tiered rate limiting (global 100/15min, auth 10/15min, registration 5/15min)
- `express.json({ limit: '1mb' })` — payload size guard

### Task 2: Supabase admin client and middleware

Create `backend/config/supabaseClient.js` using `SUPABASE_SERVICE_ROLE_KEY` (never exposed to browser).
Create `backend/middleware/authMiddleware.js` — validates `Authorization: Bearer <token>` by calling `supabase.auth.getUser()` then cross-referencing `public.profiles` for the authoritative role.
Create `backend/middleware/roleMiddleware.js` — `requireRole(...roles)` factory that gates routes by profile role.

### Task 3: Auth endpoints

Create `backend/routes/authRoutes.js` and `backend/controllers/authController.js`:
- `POST /api/auth/admin/login` — verifies profile role is `admin` before returning session
- `POST /api/auth/student/login` — verifies profile role is `student` and approval status is `approved`
- `GET /api/auth/me` — returns profile from `public.profiles` (authoritative role source for AuthGuard)

### Task 4: Admin student management CRUD

Create `backend/routes/studentRoutes.js` and `backend/controllers/studentController.js`:
- `POST /api/students/register` — admin creates student (auth user + profiles + students rows)
- `GET /api/students/profile` — student fetches their own profile
- `GET /api/students/all` — admin lists all students with attendance stats
- `PUT /api/students/:id` — admin updates student details
- `DELETE /api/students/:id` — admin deletes student (cascades auth user)
